Arquitectura de drawio-automation-platform — un normalizador que convierte XML crudo de Draw.io (o imágenes/texto) en diagramas C4 conformes a estándar.

Tres puntos de entrada alimentan el mismo motor: (1) una CLI, el módulo c4norm.cli, que se invoca como `python -m c4norm`; (2) una API REST construida con FastAPI en el paquete api; y (3) un cliente HTTP cualquiera que consume esa API.

El paquete api contiene cuatro módulos. api.main define la aplicación FastAPI y expone los endpoints POST /api/v1/diagram/normalize (recibe XML crudo), POST /api/v1/diagram/from-image (recibe una imagen) y POST /api/v1/diagram/from-text (recibe una descripción textual), más GET /health y GET /metrics. api.config define Settings (configuración por variables de entorno con Pydantic). api.schemas define los modelos Pydantic de petición y respuesta. api.linting define XMLLinter, el validador de compliance (colores, stencils, licencia ArchiMate) sobre lxml.

El corazón es el paquete c4norm. Su orquestador es c4norm.normalize, que ejecuta el pipeline en orden: primero c4norm.parse convierte el XML Draw.io en un modelo lógico (saneando mojibake y reconectando aristas huérfanas por proximidad); ese modelo lógico (Diagram, Node, Edge) y el estándar C4 canónico viven en c4norm.model. Luego c4norm.classify asigna el tipo C4 a cada nodo a través de la interfaz C4Classifier, que tiene dos implementaciones: HeuristicClassifier (determinista) y LLMClassifier (asistido por un LLM externo). Después c4norm.ground ancla los nodos de infraestructura sueltos en una zona de conectividad. A continuación c4norm.sizing dimensiona cada caja a su texto, y el subpaquete c4norm.layout calcula posiciones mediante un motor intercambiable: ElkLayout (que invoca ELK real vía elkjs sobre Node.js) con fallback a LayeredLayout (Python puro). Finalmente c4norm.emit serializa el resultado a XML C4, apoyándose en c4norm.sheet para dibujar el marco y el cajetín ISO 7200, y soportando descomposición multi-hoja.

Dos módulos generadores alimentan al normalizador desde entradas no-XML: c4norm.vision define VisionExtractor (imagen → XML Draw.io vía un LLM con visión) y c4norm.textgen define TextExtractor (descripción textual → XML Draw.io vía LLM). Ambos producen XML crudo que luego pasa por c4norm.normalize.

Tanto LLMClassifier como VisionExtractor y TextExtractor consumen un proveedor LLM externo compatible con la API de OpenAI (configurado como Alibaba Cloud MaaS). El subpaquete c4norm.layout depende de un runtime externo de Node.js que ejecuta elkjs. Toda la solución se empaqueta en un contenedor Docker que incluye Python y Node.js y sirve la API con uvicorn.
